# 前提：Python >= 3.13（上游报告问题六）。pr-agent 0.39–0.44 均按 Python 主版本二选一钉
# google-cloud-storage（<3.13 ==2.10.0 / >=3.13 ==3.12.0），单一 pin 无法同时满足两版
# Python；CI=3.13 故取 3.12.0。改 CI Python 主版本必须在目标版本上重生成本锁，勿手改该行
# （2026-07-18 PR#108 合入后 PR#109 评审轮 no_engine 根因即旧 pin 与 3.13 冲突）。
# pragent-constraints.txt —— PR-Agent venv 复现锁（.pragent-venv，与主仓 constraints.txt 平行）
# 用法（touchstone.yml 已接线）：pip install pr-agent==<PRA_VERSION> -c pragent-constraints.txt
#
# 作用边界（诚实声明，2026-08-31 pip-audit 实测，本树 = pr-agent 0.44.0 + Python 3.13）：
#   · 本锁提供【复现性】：pr-agent 0.44 起上游把多数直接依赖从精确钉（==）放宽为补丁范围
#     （aiohttp>=3.14.3,<4 / GitPython>=3.1.59,<4 / PyJWT>=2.13.0,<3 / ujson>=5.13.0,<6 /
#     dynaconf>=3.2.13,<4 …… 上游 #2881），不锁则每次重建 venv 随时间漂移；
#     升级 pr-agent 版本时须重新生成本文件并全量回归。
#   · 0.39 时代"上游硬钉带 CVE、resolver 无法越过"的死结已随 0.44 解除：本冻结树
#     pip-audit 零已知漏洞（GitPython 3.1.61 / PyJWT 2.13.0 / ujson 5.13.0 / aiohttp 3.14.3 /
#     starlette 1.6.0 / cryptography 50.0.1）。后续新 CVE 出现时重生成本锁即可吃到补丁版
#     （范围内 resolver 自由），不再需要等上游发版——SECURITY.md「供应链信任边界」据此更新。
#   · 0.44 运行时不再依赖 pytest/pytest-asyncio/pytest-cov/coverage（上游 uv 迁移移出），
#     本树较 0.39 锁少 4 个发行版。
#   · venv 自身的 pip 不受 pr-agent 管辖：workflow 建 venv 后先 --upgrade pip
#     （pip 24.0 有 5 条 PYSEC，已可修）。
